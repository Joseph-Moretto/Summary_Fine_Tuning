# Scientific Paper Summarization via Knowledge Distillation

Code, data and results for fine-tuning Llama 3 (8B and 70B) to summarize
scientific papers, using summaries written by a stronger teacher model as the
training signal. The repository covers the training runs, the evaluation
pipeline, and the per-summary analysis reported in the accompanying paper.

## Overview

The dataset is 1,500 arXiv papers from computer science, physics and
mathematics. For every paper we have the body text, the authors' abstract, and
a 150-250 word summary generated by Claude Opus 4.6 (the teacher). The papers
are split 80/10/10 into train, validation and test, stratified by domain.

Two students are fine-tuned on the 1,200 training pairs (paper text in, teacher
summary out), with the loss restricted to the summary tokens:

- Llama 3.1 8B Instruct, bf16 LoRA on a single 48 GB GPU
- Llama 3.3 70B Instruct, 4-bit QLoRA on two 48 GB GPUs

Each student and its un-tuned base model then summarize the 150 held-out test
papers. Summaries are scored against two references, the abstracts and the
teacher summaries, with ROUGE, BERTScore, BLEU and METEOR; fine-tuned vs. base
differences are tested with a paired permutation test and Wilcoxon signed-rank;
factual consistency with the source is measured with LongDocFACTScore; and the
extractiveness of each system is characterized with novel n-gram rates and
extractive fragment coverage and density. The teacher's own summaries are
scored alongside as an upper reference.

## Setup

Training and evaluation use separate conda environments (Python 3.11,
PyTorch 2.11.0 with CUDA 13.0 wheels); `setup/README.md` explains why and
lists the exact versions of the reported runs.

```bash
# Training environment
conda create -n qlora_summ_ft3 python=3.11 -y && conda activate qlora_summ_ft3
pip install torch==2.11.0 --index-url https://download.pytorch.org/whl/cu130
pip install -r setup/requirements-train.txt

# Evaluation environment (or submit setup/setup_eval_env.slurm)
conda create -n summ_eval python=3.11 -y && conda activate summ_eval
pip install torch==2.11.0 --index-url https://download.pytorch.org/whl/cu130
pip install -r setup/requirements-eval.txt
python -c "import nltk; [nltk.download(r) for r in ('punkt', 'punkt_tab', 'wordnet', 'omw-1.4')]"
```

The Llama 3 checkpoints are gated on the Hugging Face Hub; run
`huggingface-cli login` first. The job scripts read the model cache location
from `HF_HOME` (default `/scratch/$USER/HF_cache`).

The SLURM scripts carry the account, partition and GPU settings of the cluster
the experiments ran on (RTX A6000 nodes). Edit the `#SBATCH` lines for another
cluster, and submit from the repository root so that relative paths resolve:

```bash
sbatch training/run_finetune_8b.slurm
sbatch training/run_finetune_70b.slurm
sbatch evaluation/run_eval_8b.slurm
sbatch evaluation/run_eval_70b.slurm
sbatch evaluation/run_extract_per_summary.slurm
```

## Training

Two versions of the training script are kept because the two reported runs
used different ones. Both build the same prompt, the same stratified split
(seed 42, so both runs share an identical test set) and the same
completion-only loss; they differ in how papers that do not fit the context
window are handled and in a few defaults.

| | Llama 3.1 8B Instruct | Llama 3.3 70B Instruct |
|---|---|---|
| Script | `training/finetune_v1.py` | `training/finetune_v2.py` |
| Job script | `training/run_finetune_8b.slurm` | `training/run_finetune_70b.slurm` |
| Precision | bf16 LoRA, no quantization | 4-bit NF4 QLoRA, double quantization |
| LoRA rank / alpha / dropout | 16 / 32 / 0.05 | 16 / 32 / 0.10 |
| LoRA targets | q, k, v, o, gate, up, down projections | same |
| Learning rate, schedule | 2e-4, cosine, 3% warmup | 1e-4, cosine, 5% warmup |
| Effective batch size | 16 (4 x 4 accumulation) | 16 (1 x 16 accumulation) |
| Epochs | 3 | 3 |
| Max sequence length | 8,192 tokens | 8,192 tokens |
| Over-length papers | text cut at 12,000 characters | head + tail kept within a per-example token budget |
| Checkpoints | final adapter only | per epoch, best validation loss restored |
| Hardware, wall time | 1x A6000, 3 h 45 min | 2x A6000, 24 h 08 min |

`finetune_v2.py` measures, for each example, how many tokens are left for the
paper after the system prompt, instruction, title, chat-template tokens and the
teacher summary, and cuts the paper to that budget keeping roughly the first
70% and last 30%, snapping to section or paragraph boundaries. 163 of the 1,500
papers were truncated this way for the 70B run; nothing was dropped.

Each run writes the adapter, `test_paper_ids.json` (the held-out papers with
their domain labels, consumed by the evaluation scripts), `split_summary.json`
and the usual trainer metrics into its output directory. See
`training/README.md` for the full option list and the run details.

## Evaluation

`evaluation/evaluate.py` runs inference for the fine-tuned model and the base
model on the test papers, then computes all four analyses, writing
`eval_generations.json`, `eval_results.json`, `eval_report.txt`,
`significance_results.txt`, `ldfact_results.json` and
`abstractiveness_results.json` to `--output_dir`. `--metrics_only` re-scores
cached generations without loading a model, and the `--skip_*` flags disable
individual analyses. Generation uses nucleus sampling (temperature 0.7,
top-p 0.9, repetition penalty 1.1, up to 512 new tokens) with a fixed seed.

The evaluation prompt is the same for the base and the fine-tuned models. Its
wording differs slightly from the training prompt, and papers are cut to the
token budget from the front only. `evaluation/evaluate_train_aligned.py` is a
later variant that reuses the exact training prompt and the head-and-tail
truncation from `finetune_v2.py`; it is provided for follow-up work and was
not used for the numbers reported in the paper.

`evaluation/extract_per_summary.py` joins per-summary extractive density and
LongDocFACTScore on `paper_id` for every system, producing the CSVs in
`results/per_summary/` that back the density-vs-factuality analysis.

`evaluation/interactive_inference.py` is a small REPL for inspecting a trained
adapter: pick a test paper, view the exact prompt and its tokens, generate with
the adapter on and off, and compare against the abstract and teacher summary.
`evaluation/README.md` documents every metric and option.

## Results

Scores on the 150 test papers, from `results/*/eval/`. "vs. abstract" uses
the authors' abstracts as reference, "vs. teacher" the Claude summaries.
LongDocFACTScore (LDFS) is a BARTScore-based log-likelihood, so values are
negative and higher is better.

| System | R-1 | R-2 | R-L | BERTScore F1 | R-L vs. teacher | BERTScore F1 vs. teacher | LDFS | Avg. words |
|---|---|---|---|---|---|---|---|---|
| Teacher (Claude Opus 4.6) | 0.4887 | 0.1861 | 0.2582 | 0.6536 | | | -4.184 | 221.9 |
| Llama 3.1 8B, base | 0.4280 | 0.1608 | 0.2216 | 0.6050 | 0.3001 | 0.6684 | -4.072 | 288.9 |
| Llama 3.1 8B, fine-tuned | 0.4663 | 0.1640 | 0.2374 | 0.6435 | 0.3902 | 0.7422 | -4.327 | 212.6 |
| Llama 3.3 70B, base | 0.4594 | 0.1712 | 0.2356 | 0.6228 | 0.3106 | 0.6826 | -3.761 | 198.4 |
| Llama 3.3 70B, fine-tuned | 0.4692 | 0.1671 | 0.2400 | 0.6455 | 0.4315 | 0.7599 | -4.391 | 217.4 |

Fine-tuning moves both students toward the teacher on every metric against
the teacher summaries (all differences significant at p < 0.001 with large
effect sizes) and, against the abstracts, improves ROUGE-1 and BERTScore F1
significantly at both scales. The base models are markedly more extractive
(extractive density 5.2 and 4.1 versus 2.5-2.7 for the fine-tuned models and
the teacher), which is the context for their higher LongDocFACTScore.
`results/README.md` has the complete tables: all metrics, per-domain
breakdowns, significance tests, abstractiveness measures and word counts for
both runs.

## Reproducibility notes

- The split is deterministic given the data files and seed 42; both runs
  produced byte-identical `test_paper_ids.json`.
- The adapter weight files exceed GitHub's 100 MB file limit and are not in
  the repository; `adapter_config.json`, the tokenizer configuration and every
  training log and metric are. The adapters can be retrained with the job
  scripts in `training/`.
- The scripts that built `data/` (arXiv extraction and teacher summary
  generation) are not part of this repository.
- `bert-score` is imported with a small patch that truncates inputs to
  DeBERTa's 512-token limit; see `_patch_bertscore_overflow` in `evaluate.py`.
